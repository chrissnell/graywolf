Cursor-on-Target

Drop a named object on the live map and beacon it under your station callsign

A Cursor-on-Target (CoT) is a one-off APRS object — a name, an icon, a comment, and a position — that you drop directly from the Live Map instead of pre-configuring a beacon. It’s built for the case where you need to mark something right now: an aid station, a hazard, a staging area, a rally point — and you want it on the air immediately without opening the Beacons page first.

A CoT transmits once immediately, then automatically retransmits a few more times on a schedule that spaces out over time, so the object stays visible on other stations’ maps for a while without you having to babysit it or clutter the frequency with a beacon that repeats forever.

ⓘ

CoT objects always transmit under your station callsign — there is no per-object override. Set your station callsign before adding one; graywolf refuses to create a CoT target otherwise.

Adding a Cursor-on-Target

  1. Open the Live Map.
  2. Right-click (or long-press on touch) the spot you want to mark. Add CoT is the first item in the context menu.
  3. Fill in the dialog:
    • Object Name — up to 9 characters, shown as the object’s label on APRS maps.
    • Icon — defaults to the primary-table “/D” symbol; click Choose… to pick a different one from the same symbol picker beacons and fixed points use.
    • Comment — free text appended to the object report.
    • Latitude / Longitude — read-only, filled in from where you clicked.
  4. Click Send. It enables once Object Name and Comment are both filled in. The object transmits immediately and the dialog closes.

The retransmit schedule

After the immediate first send, graywolf keeps retransmitting the object a few more times so it doesn’t vanish from other stations’ maps the moment your first packet ages out. Each later transmit is spaced out further than the last, controlled by three numbers (configured on the Cursor-on-Target Settings tab):

  • Number of Transmits — the total number of sends, counting the immediate first one. Default 4.
  • 2nd TX Delay — how long after the first send the second one fires. Default 300 seconds (5 minutes).
  • Decay Factor — each later delay is the previous one multiplied by this factor. Default 2 (each gap doubles).

With the defaults (4 / 300 / 2), the schedule looks like this:

TransmitOffsetTime
TX 10 s00:00:00
TX 2300 s00:05:00
TX 3600 s00:10:00
TX 41200 s00:20:00

The Cursor-on-Target Settings tab shows this same preview table live as you adjust the three numbers, so you can see the exact pattern before saving.

Clicking Beacon Now on a CoT target (see below) sends it immediately but never counts against this schedule — it doesn’t advance the transmit count or change when the next automatic retransmit fires.

Cursor-on-Target Settings

Global parameters live on the Beacon Settings page (Preferences → Beacons, or directly from the Beacons page), under the Cursor-on-Target Settings tab. Every new CoT object snapshots these settings for itself at the moment it’s created — changing them later never affects a target that already exists, only ones created afterward.

FieldDefaultDescription
type object Reserved for a future non-object CoT kind. Only “Object” exists today.
send_path rf Same three choices as beacons: RF only, RF + APRS-IS, or APRS-IS only (no radio). Saving with APRS-IS only auto-enables the iGate the same way an APRS-IS-only beacon does.
channel Auto Radio channel new CoT targets transmit on. Hidden when Send To is APRS-IS only.
destination APGRWO APRS tocall identifying the originating software.
path WIDE1-1,WIDE2-1 Digipeater path.
num_transmits 4 Total sends including the immediate first one.
second_tx_delay_seconds 300 Delay before the second transmit.
decay_factor 2 Multiplies each successive delay — see the retransmit schedule above.

Viewing and managing Cursor-on-Targets

The Beacons page has three tabs: Beacons, Active Cursor-on-Targets, and Inactive Cursor-on-Targets. A CoT target moves from Active to Inactive once it has been transmitted num_transmits times — it stays listed there rather than disappearing, so you can still review it, fire it again with Beacon Now, or delete it.

Each card shows the same destination/path/position detail rows as a beacon card, plus a TX Count row reading x/n — how many times it has been automatically sent, out of the configured total. Two buttons are available:

  • Beacon Now — sends it immediately without affecting the TX Count.
  • Delete — removes the target and cancels any remaining scheduled retransmits.
ⓘ

Deleting a Cursor-on-Target (single or via Delete all) also transmits an APRS object-kill report for it — the same object name and position, but marked dead instead of live. Compliant radios and apps that recognize the kill status remove the object from their own list instead of waiting for it to age out on its own. This send is best-effort: if the channel is unreachable, the target is still deleted from graywolf.

The Inactive Cursor-on-Targets tab also has a Delete all button above the list, for clearing out every exhausted target at once.
