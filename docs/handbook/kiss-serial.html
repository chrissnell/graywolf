KISS over Serial

Connect a hardware TNC or radio with a built-in KISS serial port directly to graywolf over a USB or RS-232 serial link.

Overview

Some TNCs and radios speak KISS natively over a serial port rather than over TCP. Connecting one of these devices lets graywolf use it as a full radio channel — beacon into it, digipeat across it, and iGate from it — without an audio modem or a network connection between graywolf and the device.

Common examples include the Kenwood TH-D75 and TH-D74 handhelds (which expose a USB serial port and speak KISS when placed in packet mode), Mobilinkd TNCs (which attach over Bluetooth serial or USB serial), and the Kantronics KPC-3+ (classic RS-232 TNC with a KISS mode). Any device that presents a serial port and speaks the KISS protocol works.

Graywolf opens the serial port, reads KISS frames as they arrive, and writes KISS frames when transmitting. The device handles all RF carrier sensing, timing, and actual transmission; graywolf is just the packet router on top.

i

With the default Native KISS initialization profile, the radio or TNC must already be in KISS mode. Graywolf leaves that transport unchanged. For a Kenwood TM-D700 or TM-D710, select the dedicated initialization profile described below.

Device Paths

When graywolf asks for a device path, enter the operating-system path to the serial port:

PlatformTypical paths
Linux /dev/ttyACM0, /dev/ttyACM1 (USB CDC-ACM devices such as Mobilinkd and AIOC), /dev/ttyUSB0, /dev/ttyUSB1 (USB-to-serial adapters, FTDI and CP210x chips)
macOS /dev/cu.usbmodem*, /dev/cu.usbserial-* — use /dev/cu.* (the call-out device), not /dev/tty.* (the dial-in device), to avoid blocking on open.
Windows COM3, COM4, etc. Check Device Manager under “Ports (COM & LPT)” for the assigned port number.

On Linux, if you are unsure which path corresponds to your device, unplug it, run ls /dev/ttyACM* /dev/ttyUSB*, plug it back in, and run the command again. The new entry is your device. The dmesg output also shows the assigned path when the kernel recognizes the USB device.

✓

Pin the device node so it never moves. USB serial paths like /dev/ttyUSB0 can jump to ttyUSB1 after a reboot or when another USB serial device is present, which breaks the configured path. Add a udev rule that creates a stable symlink keyed to the device’s serial number, then point graywolf at the symlink: 

# /etc/udev/rules.d/99-graywolf-tnc.rules
SUBSYSTEM=="tty", ATTRS{idVendor}=="0403", ATTRS{idProduct}=="6015", ATTRS{serial}=="YOUR_SERIAL", SYMLINK+="lorapi"

Find the values with udevadm info -a -n /dev/ttyUSB0 | grep -E 'idVendor|idProduct|serial', reload with sudo udevadm control --reload && sudo udevadm trigger, then set the serial device in graywolf to /dev/lorapi. (The example IDs 0403:6015 are the FTDI chip on the RPC Electronics LoRa-Pi; use your own device’s IDs.)

Baud Rate

The baud rate you enter in graywolf must match the baud rate configured on the device. Common values:

  • 9600 — the most common default for TNCs and many radios with built-in KISS serial support.
  • 4800 — used by some older TNCs and low-speed configurations.
  • 19200, 38400, 57600, 115200 — higher speeds used by some modern USB TNCs; check your device's documentation.

A baud-rate mismatch produces garbage framing. If the KISS interface appears connected but no frames arrive (or arrive as decode errors), verify that both sides are set to the same rate.

Configuration

Step 1 — Create a KISS-only channel

  1. Open Radio → Channels in the web UI.
  2. Click + Add Channel.
  3. In the channel-type segmented control at the top of the form, choose KISS-TNC only. The audio device, modem type, and TX timing fields disappear — a KISS-only channel is a logical routing lane, not a modulated radio channel.
  4. Name it to reflect the attached device (for example, TH-D75 or Mobilinkd). Give it a channel number that does not collide with your existing RF channels.
  5. Click Save. The channel appears on the list with a KISS-TNC only badge. Its backing shows — Unbound until you attach the serial KISS interface below.

Step 2 — Create a serial KISS interface

  1. Open Interfaces → KISS TNC (the page is titled KISS Interfaces).
  2. Click + Add KISS.
  3. In the Type field, choose Serial.
  4. In Serial Device, enter the operating-system path to the serial port (see Device Paths above).
  5. Set Baud Rate to match the rate configured on the device (9600 is the most common starting point).
  6. In the Channel picker, select the KISS-only channel you just created.
  7. Set Mode to TNC. In TNC mode the interface is treated as a radio, not a software client. This also reveals the transmit opt-in checkbox.
  8. In TNC initialization, leave Native KISS selected for a device already speaking KISS, or choose Kenwood TM-D700 or Kenwood TM-D710 / TM-D710G for the corresponding radio to switch its TNC into KISS automatically.
  9. For an explicit Kenwood model profile, choose Radio packet speed: preserve the firmware setting (default), 1200, or 9600. This RF speed is independent of the serial Baud Rate used by the computer.
  10. Check the box labeled Allow digipeater/beacon/iGate to transmit on this interface to allow graywolf's TX pipeline to send frames to the device. Without this checkbox the interface only receives.
  11. Click Create. Graywolf opens the serial port immediately. The row's status badge shows Connected if the port opened successfully. The channel's backing on the Channels page flips to ● Live.
!

Select the profile matching your radio model. Only the legacy profile requires PACKET mode in advance. The serial baud rate must match its computer port. Close any other terminal application before enabling the interface in Graywolf.

Kenwood TM-D700 / TM-D710 Initialization

Select the appropriate data band, frequency and radio packet speed on the radio, and connect its TNC computer port. On a TM-D710/G, this is the COM port behind the operation panel, not the PC port on the radio body. Select Kenwood TM-D700 or Kenwood TM-D710 / TM-D710G under TNC initialization on a Serial or USB Serial interface in TNC mode. Model profiles select PACKET mode then KISS, taking over from the radio's internal APRS application. They do not configure the radio frequency, callsign, serial speed, or Graywolf's transmit opt-in setting. The separate Radio packet speed setting defaults to Preserve radio setting / Conserver: no HBAUD command is sent, so the firmware's restored packet-speed setting remains in use. Select 1200 or 9600 to explicitly set and verify HBAUD after stabilization.

ProfileRadio-control sequence
TM-D700Synchronize, send the initial AI 1, then request TC 1 and require its distinct TS 1 reply (verified on the real D700). Repeat and verify AI 1 in radio-control mode before verifying ID TM-D700. Send TNC 2, wait for mode stabilization, select operating band A with BC 0,0 and data band A with DTB 0, then send TC 0, pause briefly and send CR to obtain cmd:. This follows the supplied UI-View TM-D700.CMD sequence while keeping frequency and shift configured on the radio; the sample file's fixed 144.800 MHz command is not sent.
TM-D710 / GSynchronize, require TS 1 after TC 1, verify ID TM-D710 (including A, E, P and G/GA/GE replies), for the ID TM-D710P reply send TN 2,0 directly (PACKET on band A, following the supplied UI-View initialization file; this firmware rejects a bare TN query). Other variants query TN, then send TN 2,<band> preserving the reported band selection (A, B or split TX/RX). Wait for cmd:.

On every open or reconnect, synchronization uses three Ctrl-C characters, the binary KISS return sequence C0 FF C0, a short pause, then three Ctrl-C characters and CR. On both models, the control-mode request TC 1 is retried up to three times with 1.5-second reply deadlines if the radio misses the first request during KISS exit. A single reader preserves replies across these waits. The model-specific sequence above follows. After the first PACKET prompt, Graywolf drains delayed startup replies until a 200 ms quiet interval (at most one second) before setting HBAUD or ECHO; startup errors are not used as replies to later commands. After the mode-selection acknowledgement (TNC 2 or TN 2,<band>), Graywolf waits four seconds before continuing, even if an early cmd: is already present. Some firmware restores saved state and speed during this interval. When an RF speed is selected, Graywolf sets HBAUD 1200 or HBAUD 9600, waits for its setting response, queries HBAUD and verifies the current value. A mismatch or rejected command fails initialization. It first disables command echo with ECHO OFF and requires the setting reply and prompt. Finally it sends KISS ON, checks the response and prompt, sends RESTART and waits five seconds. During this wait, it continues reading: an explicit rejection or a serial disconnection fails initialization instead of showing Connected. Startup traffic is buffered (up to 256 KiB) and delivered unchanged to the KISS decoder; error-looking text inside KISS frames is treated as payload, not as a command rejection. The interface stays Connecting until this finishes; initialization has a 30-second deadline and failures use normal reconnect backoff. Startup bytes are preserved for the KISS decoder.

For Serial, USB Serial and Bluetooth interfaces, expand the connection status to inspect diagnostics and use Reconnect. This closes an active serial session or interrupts initialization and reopens the port immediately; it also bypasses a pending retry delay. With a Kenwood model profile, Graywolf automatically reinitializes the radio if it receives a new command prompt, the Kenwood startup banner, an ASCII TNC2 monitor header outside KISS, or the exact altered echo of a recently sent KISS frame with its AX.25 Ctrl-C byte consumed by command mode. Valid binary APRS payload is not interpreted as a prompt. A powered USB adapter alone cannot reveal a completely silent radio reset, and radio silence does not trigger resets.

Stopping the interface closes the serial port and leaves the radio in KISS mode; the profile will synchronize it again when reopened. A failed initialization may leave the radio in command/control mode; check the displayed error and restore the desired mode manually when necessary. To use a command terminal manually, disable the Graywolf interface first and send the binary return sequence from the terminal. KISS provides no mandatory startup acknowledgement: Connected means the serial session is ready, not that a radio exchange succeeded. Reconnect Behavior

If the serial device is unplugged or the port closes unexpectedly, graywolf's serial supervisor backs off and automatically retries opening the port. You do not need to restart the daemon. When the device is plugged back in and the operating system reassigns the same path, graywolf reconnects and the channel returns to ● Live status.

Editing the device path, baud rate, or mode on the KISS TNC page and clicking Save triggers a hot reload: graywolf closes the existing connection and re-opens the port with the new settings. No daemon restart is required.

Troubleshooting

Linux permission denied (EACCES)

On Linux the serial port device is typically owned by the dialout group (or uucp on some distributions). The user running graywolf must be a member of that group. Add the user with: 

sudo usermod -aG dialout <username>

You must log out and log back in (or start a new login session) for the group change to take effect. If graywolf runs as the graywolf system user (the default for deb/rpm/AUR package installs), the post-install script adds that user to dialout automatically.

Port busy (EBUSY / "device or resource busy")

Another process holds the serial port open. Common culprits are a terminal emulator left open (minicom, screen, picocom), a competing TNC application, or the ModemManager service on Linux (which probes newly-connected serial devices). Check with: 

fuser /dev/ttyACM0

That command prints the PID of any process holding the device. On systems running ModemManager you can stop it for a session with sudo systemctl stop ModemManager or add a udev rule to prevent it from touching your TNC's USB vendor/product ID.

Interface connects but no frames arrive

Check in order:

  1. Confirm the device is actually in KISS mode. Most radios and TNCs default to a human-readable command mode and must be explicitly switched. Consult your device's manual.
  2. Verify the baud rate matches on both sides. A mismatch produces garbage bytes that the KISS framer discards.
  3. Confirm the device is transmitting. On a radio such as the TH-D75, the APRS channel must be active and a beacon must be due — the port is silent between packets.
  4. Check the Logs page in the graywolf UI for any serial framing or open errors.

My beacon on the channel does not transmit

Likely causes:

  • Wrong mode — the Logs show txbackend: no backend registered for channel. The interface is set to Modem mode. A hardware TNC/modem has no software modem behind it, so Modem mode registers no transmit backend and every outbound frame is dropped before it reaches the device (RX still works, which is why the interface looks healthy). Change Mode to TNC, tick the transmit checkbox, and save. See Mode: Modem vs. TNC.
  • Transmit checkbox is off. Open the KISS interface, confirm Mode is TNC and the Allow digipeater/beacon/iGate to transmit on this interface box is checked.
  • Port is not open. The status badge on the KISS page shows Reconnecting if graywolf cannot open the port. Confirm the device is connected and the path is correct.
  • Channel is unbound. If you created the channel but never attached the serial interface to it, the channel's backing is — Unbound and no frame goes anywhere.
